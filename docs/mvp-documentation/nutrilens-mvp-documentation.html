NutriLens: MVP Walkthrough Documentation

Prepared by Afiq Roslan (Builder)
SAIA2183: AI for Tech Venture
Faculty of Artificial Intelligence, Universiti Teknologi Malaysia

NutriLens is an interactive Streamlit MVP built to test one core assumption: will budget-conscious users use a tool that recommends meals based on budget and nutrition goal before they order? This document walks through the current working prototype as it behaves today. Each section shows an implemented interaction, what it does, and where relevant, the validation insight it responds to.

01

Set your preferences, then find your match

Every recommendation starts in the sidebar, now labelled ‘What are you looking for?’. A user selects one of eight budget tiers from RM6 to RM25 under ‘Your budget’ and picks a nutrition goal — High Protein, Low Calorie, Best Value, or Balanced — under ‘Your nutrition goal’. Both fields start unselected, so the app opens on a simple three-step onboarding screen instead of jumping straight to results.

Recommendations only appear once both fields are set and the user clicks ‘Find My Best Meal’; changing a dropdown afterwards does not recalculate results until the button is clicked again. In this walkthrough, the user sets RM12 and High Protein.

02

View the Best Match and alternatives

After clicking ‘Find My Best Meal’, NutriLens removes meals above the selected budget, then ranks the eligible options using a Match Score from 0-100 for the chosen nutrition goal. The Best Match card leads with a large, clearly labelled Match Score ring placed directly beside the meal photo, with the meal name, price, and macros beside it and the ‘Why this meal?’ reasons shown immediately underneath. In this example, Grilled Fish with Rice is the Best Match at 68/100.

Match Score represents relative compatibility within the eligible options; it is not a health or medical rating.

03

See why the Best Match was chosen

NutriLens explains the reasoning behind its recommendations instead of showing only a score. The Best Match card shows its ‘Why this meal?’ reasons directly beneath the meal details by default — no expanding required — linking the recommendation back to measurable factors such as budget, protein content, and the selected nutrition goal. Alternative cards keep the same explanation in a compact expander to stay scannable, while still giving the Match Score equal visual weight beside the meal photo.

04

Search and evaluate a specific meal

Users who already know what they are considering can use ‘Already have a meal in mind?’ in the sidebar to search for a meal by name instead of relying only on the ranked list. Searching for Nasi Lemak displays its full nutrition profile and evaluates it against the current budget and goal. The Best Match remains visible underneath, allowing the user to compare the meal they intended to order with a stronger-ranked alternative.

This search works even before ‘Find My Best Meal’ has been clicked, as long as a budget and goal are already selected; if either is missing, NutriLens asks the user to set both first before it will evaluate the meal.

Validation-driven refinement: manual search was retained as a lower-friction pathway for users who preferred looking up a known dish instead of scanning or uploading an image.
05

Apply the prototype poultry filter

Users who want to avoid poultry can check ‘Yes, avoid poultry’ under ‘Do you need to avoid poultry?’ in the sidebar. Meals known to contain poultry are removed before ranking. Meals whose poultry status is unknown remain visible but are clearly marked ‘Poultry status unverified’ rather than implied safe. The sidebar note now reads: “Prototype only: Poultry information is based on MVP metadata and may be incomplete. Not intended for commercial or allergy-safety use.”

Validation-driven refinement: this narrow filter was added after dietary-avoidance feedback and deliberately kept limited in scope for the MVP.

06

Preview an uploaded meal or menu photo

A user can upload a meal or menu photo under ‘Have a photo?’ in the sidebar and immediately preview it inside NutriLens. In the current MVP, no recognition or analysis is performed on the uploaded photo. Uploading a photo does not change the recommendation results; recommendations continue to use the selected budget and nutrition goal. The interface states this boundary directly: “Photo analysis isn’t available yet. For now, your photo will only be previewed.”

07

Review how NutriLens works and its prototype limitations

Selecting ‘About NutriLens’ from the sidebar navigation (now labelled ‘My Recommendations’ and ‘About NutriLens’) explains the recommendation approach and consolidates the prototype’s limitations in one place. Current nutrition and meal information comes from prototype data rather than a live restaurant source. Poultry metadata is not verified ingredient data, meal photos are illustrative rather than verified vendor photography, image upload performs no recognition or analysis, and user activity is not saved between sessions.

Prototype scope

The current NutriLens MVP uses a static prototype dataset of 15 meals and does not yet connect to live restaurant menus, user accounts, or persistent history. Match Score represents relative compatibility with the selected goal among eligible meals; it is not a health or medical rating. The poultry filter relies on prototype metadata rather than verified ingredient or allergy information, and uploaded images are previewed only. These boundaries are intentional: the MVP is designed to test the usefulness of budget- and nutrition-based meal recommendations before investing in full image recognition, restaurant integration, and persistent user features.
